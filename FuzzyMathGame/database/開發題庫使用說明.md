# MySQL 開發題庫（2026-10-20）

## 使用

網址 http://127.0.0.1:5000/ 。目前背景測試服務使用 database/run_dev_server.py；這個服務不會自動重載 Python。之後重開電腦可雙擊專案根目錄的啟動程式.bat。若已經有後端在 5000 埠執行，不要同時啟動第二份。

database/runtime.json 是模式的優先設定：mysql_dev 讀本次開發庫；local 回到先前四題練習版；mysql 使用原同學題庫（須另有原始 SQL）。不要將 FUZZY_DB_NAME 改成開發庫後直接使用舊 mysql 模式：兩者結構尚未相容。

## 真正新增了什麼

獨立資料庫 fuzzy_math_game_dev。bank_meta 記錄 schema 版本；chapter、question_type、question_spec、spec_parameter、solution_step、solution_option 管理題目。共 8 題型、40 個參數範圍規格、130 個步驟、650 個錯解候選規則。錯解候選先去重，再選 3 個加上正解，最後只回 4 個選項。

|章節|代碼|內容|步數|
|---|---|---|---|
|1|F09|基本一次方程式|2|
|2|L01|一次多項式直接代入極限|2|
|3|D02|單項式冪次微分|3|
|4|R01|依乘法法則求單項式乘積的導數|4|
|5|A01|二次函數遞增、遞減區間|4|
|6|I01|正整數冪次不定積分，包含 C|3|
|7|T01|下限為 0 的一次函數定積分|4|
|8|U01|正值直線與座標軸之間的面積|4|

每個題型各有 1–5 五個規格，但目前差別主要是參數範圍，尚未經老師確認認知難度。題型皆自編，未使用或宣稱取得公開題庫。八章目前各有一個代表題型，這不等於各章完整題庫。

這是先驗證完整流程的精簡開發模型：參數直接存 spec_parameter，衍生值用有序 JSON 規則，尚未實作規劃中的 parameter_definition、generation_rule、blank_rule 與學習紀錄。正式題庫原始 DDL 未取得，日後須寫欄位轉換 migration，不直接覆蓋同學資料。

## 在另一台電腦匯入

用 Workbench 開啟並執行 schema.sql，接著執行 seed.sql。僅在全新開發庫匯入 seed.sql；它會在重複主鍵時報錯，不覆蓋人工修改。把本機 MySQL 密碼填在自己的啟動程式.bat，不要將含密碼的啟動檔上傳 GitHub。

或在本機設定好連線後執行 python database/init_dev_bank.py。初始化器遇到已初始化的版本 1 或 2 開發庫只回報、不改資料；遇到不認識的既有庫會停止。MySQL DDL 不是整體可回滾，第一次建表中途失敗要先檢查，不能假設所有表自動撤銷。

schema.sql 與 seed.sql 是可重現初始題庫，不是未來人工修改後的即時備份。修改題庫後，請用 Workbench Data Export 匯出 fuzzy_math_game_dev 的結構和資料，保存後再做遷移。不要刪除原庫來試匯入。

## 驗證與限制

執行 python tests/test_dev_bank.py（需要 MySQL 連線）。已核對 4000 組隨機題的數學答案、正確係數與指數、每步選項唯一性、唯一正解、API 邊界及運算白名單。前端語法通過 node --check js/main.js。瀏覽器已完整走完三步微分題並觀察到能力值增加，另確認定積分上下限與四步選項顯示。

當前仍由前端持有正誤和判分，不適合可信成績評量；後端作答驗證與紀錄是下一階段。新模式只接目前遊戲用的 config 與 generate-with-steps API；舊 /api/db-check、填空與答案檢查等仍服務原始 mysql 模式，不能視為新模式已整合的端點。


## 第 4、5、8 章升級

舊的版本 1 開發庫執行 python database/upgrade_dev_bank.py；只新增三個題型及 schema 版本 2 標記，既有五種題型不更新、不刪除。重跑會辨識版本並跳過。migration_002.sql 是同等內容的 SQL；已匯入新版完整 seed.sql 的電腦不需再套用 migration_002.sql。

目前 MySQL 開發庫已套用升級，八章選單均可開啟。新增三題型的四步解法與分數臨界點經過獨立公式核對；瀏覽器確認三個章節都能載入，並完整走完第五章四步與能力值更新。
